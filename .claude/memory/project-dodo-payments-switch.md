**Credential field confusion resolved 2026-09-16 (user asked "endpoint id or signing secret? i have added api key"):** in the Dodo dashboard the user needs **two** separate credentials, not one and not an "endpoint ID" — (a) **API key** (`dodo_test_…`, Developer → API Keys, mode-dependent) for the server calling Dodo, and (b) **webhook signing secret** (`whsec_…`, shown on the webhook endpoint's **Overview** tab in Developer → Webhooks) for verifying Dodo→server calls. The **endpoint ID is never added to any config** — Dodo keeps it internally; the app never references it. Dodo **signatures follow the Standard Webhooks spec**: HMAC-SHA256 over `webhook-id` + `.` + `webhook-timestamp` + `.` + raw payload, sent in the **`webhook-signature`** header (plus `webhook-id`/`webhook-timestamp`), verified via the SDK's `unwrap()` with `webhookKey` — materially different from Razorpay's `x-razorpay-signature` over the raw body, so the existing Razorpay webhook route cannot be reused as-is. **Dodo checkout is hosted** (server creates a checkout session, customer is redirected) ⇒ there is **no `NEXT_PUBLIC_DODO_*` client key at all**, unlike `NEXT_PUBLIC_RAZORPAY_KEY_ID`.
